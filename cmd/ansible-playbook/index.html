ansible-playbook

Run Ansible playbooks to automate multi-host configuration.

high riskPlaybooks run against real hosts; always use --check first.
⚠ Risks & cautions
  • Run with --check --diff --limit <host> first.
  • Without --limit the play targets every host matched by its hosts: pattern.
  • Use serial: and max_fail_percentage in the play to roll out gradually.
Safer / dry-run alternatives
ansible-playbook site.yml --check --diff --limit <host>Dry-run on a single host.
ansible-playbook site.yml --list-hostsSee which hosts would be targeted.
What it does

ansible-playbook executes YAML playbooks that define desired state across managed hosts. Supports tags for selective execution, limits for targeting host subsets, and check mode for dry-run previews. The --diff flag shows exactly what files will change.

Common flags
FlagMeaning
-i --inventoryInventory file or directory
--checkDry run — don't make changes
--diffShow diffs of changed files
--limitLimit execution to specific hosts/groups
--tagsOnly run tasks with these tags
--skip-tagsSkip tasks with these tags
-v/-vv/-vvvVerbosity levels

Pro tip

Always run with `--check --diff` before the real run in production — it shows exactly what would change without risk. Add this as a required CI step before any production ansible run.
