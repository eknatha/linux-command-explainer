⚠ Risks & cautions
  • Ad-hoc shell/command modules run on every matched host in parallel.
  • Check which hosts match first with --list-hosts.
  • Prefer idempotent modules over `shell` so reruns are safe.
What it does

Ansible ad-hoc commands run single module tasks against inventory hosts without writing a playbook. Useful for quick checks, one-time changes, and testing connectivity. The -m flag selects the module; -a passes arguments.

Common flags
FlagMeaning
-m --module-nameAnsible module to run
-a --argsModule arguments
-i --inventoryInventory file or host list
-u --userRemote user
--becomeRun with privilege escalation (sudo)
-f --forksParallel processes (default: 5)

Pro tip

Use `ansible all -m ping -i inventory.ini` as a connectivity health check before running playbooks — catches SSH key issues and unreachable hosts before they cause partial failures.
