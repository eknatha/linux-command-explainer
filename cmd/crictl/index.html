crictl

CLI for CRI-compatible container runtimes (containerd, CRI-O).

medium risk

medium riskLow-level runtime access; bypasses Kubernetes scheduling.
⚠ Risks & cautions
  • Bypasses the Kubernetes API — removing containers/pods with crictl leaves the kubelet and API server inconsistent.
  • Usually requires root on the node; mistakes affect every pod on that node.
What it does

crictl is the kubectl-equivalent for the Container Runtime Interface layer — directly managing containers and images in containerd or CRI-O without going through Kubernetes. Essential on K8s nodes when kubelet is broken or for low-level debugging.

Pro tip

Use crictl when kubelet is down or a pod won't schedule but the container exists — `crictl ps -a` shows all containers at the runtime level regardless of Kubernetes state.
