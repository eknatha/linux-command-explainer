cron (advanced)

Schedule recurring tasks using the system cron daemon.

⚠ Risks & cautions
  • Cron runs silently — send output to a log or mail so failures are noticed.
  • Use full paths and set PATH explicitly in the crontab.
  • Prevent overlapping runs with `flock -n /tmp/job.lock <command>`.
What it does

Cron runs scheduled commands based on a time expression (minute hour day month weekday). System cron jobs live in /etc/cron.d/, /etc/cron.daily/, etc. User cron jobs are managed via crontab. Each field: minute(0-59) hour(0-23) day(1-31) month(1-12) weekday(0-7).

Pro tip

Always redirect cron output: `command >> /var/log/myjob.log 2>&1`. Without redirection, errors go to the user's mail (often ignored). Also set MAILTO='' in crontab to suppress email if not needed.
