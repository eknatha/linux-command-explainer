docker exec

Execute commands inside a running Docker container.

medium risk

medium riskCan modify container state; production containers should be treated as immutable.
⚠ Risks & cautions
  • Changes made inside a running container are lost on restart and are not tracked in Git.
  • In production, exec bypasses your deployment pipeline’s audit trail — prefer logs/metrics or a dedicated debug container.
  • Secrets passed with -e are visible in `docker inspect` and the process list.
What it does

docker exec runs commands in running containers. The -it flags attach an interactive terminal. Used for debugging — checking configs, inspecting the filesystem, testing connectivity — without rebuilding the image.

Common flags
FlagMeaning
-i --interactiveKeep STDIN open
-t --ttyAllocate a pseudo-TTY
-e --envSet environment variables
-u --userRun as specified user
-w --workdirSet working directory

Pro tip

If bash isn't available, try `docker exec -it container sh` — Alpine-based images don't include bash. Also try `docker exec -it container /bin/ash`.
