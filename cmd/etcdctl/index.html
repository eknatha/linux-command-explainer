high risketcd holds all cluster state; deletes or restores can wipe the cluster.
⚠ Risks & cautions
  • Never write/delete keys directly in a Kubernetes etcd.
  • Test snapshot restores regularly.
  • Protect certs; etcd contains Secrets in clear unless encryption at rest is on.
Safer / dry-run alternatives
etcdctl snapshot save <file>Back up first
What it does

Reads/writes etcd keys and manages snapshots/members.
