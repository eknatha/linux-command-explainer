git cherry-pick

Apply specific commits from one branch to another.

medium risk

medium riskCan create duplicate commits and cause conflicts.
⚠ Risks & cautions
  • Creates a duplicate commit with a new hash — later merges may conflict or apply the change twice.
  • Use -x to record the original commit hash in the message for traceability.
What it does

git cherry-pick applies the changes introduced by specific commits (by hash) to the current branch, creating new commits with the same changes. Useful for backporting fixes to release branches without merging all changes.

Common flags
FlagMeaning
-n --no-commitApply changes without creating a commit
-xAppend original commit hash to message
--abortCancel cherry-pick in progress
--continueContinue after resolving conflicts
Examples

Pro tip

Use `git cherry-pick -x` to include the original commit hash in the message — creates a paper trail linking the backport to the original fix, invaluable for tracking.
