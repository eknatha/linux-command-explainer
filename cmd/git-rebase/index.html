git rebase

Reapply commits on top of another base commit; rewrite history.

high risk

high riskRewrites commit history; dangerous on shared/public branches.
⚠ Risks & cautions
  • Rewrites commit hashes — never rebase commits that others have already pulled.
  • Wrongly resolved conflicts during a rebase silently drop changes; review with `git diff ORIG_HEAD`.
  • You can abort an unfinished rebase with `git rebase --abort`; afterwards recover with `git reflog`.
Safer / dry-run alternatives
git branch backup-before-rebaseLeave a pointer to the old history so you can always reset to it.
git reflogFind the pre-rebase commit if something goes wrong.
What it does

git rebase replays commits from one branch on top of another, producing a linear history. Interactive rebase (-i) lets you squash, reorder, edit, and drop commits. Never rebase public/shared branches — it rewrites history and forces conflicts for others.

Common flags
FlagMeaning
-i --interactiveInteractive rebase: edit, squash, reorder commits
--ontoRebase onto a specific commit
--abortAbort and restore original state

Pro tip

Use interactive rebase (`git rebase -i HEAD~N`) before raising PRs to squash fixup commits and write meaningful commit messages — keeps the project history clean and reviewable.
