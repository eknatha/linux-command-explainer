Query and display systemd journal logs.

⚠ Risks & cautions
  • Logs may contain secrets and personal data; `--vacuum-size/--vacuum-time` permanently deletes old journals.
What it does

journalctl is the primary tool for accessing systemd's structured binary journal. It supports filtering by unit, time range, priority, and boot. Unlike tail on flat log files, it understands log metadata and allows complex structured queries.

Common flags
FlagMeaning
-u --unitFilter by systemd service unit
-f --followFollow journal in real time
-n --linesShow last N lines
-p --priorityFilter by priority (0=emerg to 7=debug)
--sinceShow logs since a timestamp
--untilShow logs until a timestamp
-b --bootShow logs from current boot (-1 for previous)
-o --outputOutput format: json, json-pretty, short, verbose

Pro tip

Use `journalctl -b -1 -p err` to review errors from the previous boot after a crash — far faster than reconstructing the timeline from multiple log files.
