kubectl apply

Apply a Kubernetes manifest to create or update resources.

medium risk

medium riskModifies live cluster state; validate manifests before applying.
⚠ Risks & cautions
  • Applies immediately — run `kubectl diff -f` first.
  • A manifest with the wrong namespace or an old image tag can roll production back.
  • --prune and --force can delete or recreate objects.
Safer / dry-run alternatives
kubectl diff -f manifest.yamlSee exactly what would change.
kubectl apply -f manifest.yaml --dry-run=serverValidate against the API server and admission webhooks.
What it does

kubectl apply declaratively applies resource manifests from files or directories. It creates resources if they don't exist, and updates them if they do — using server-side merge. Always dry-run first in production with --dry-run=server.

Common flags
FlagMeaning
-f --filenameFile, directory, or URL
-R --recursiveProcess directories recursively
--dry-runclient or server — preview without applying
--validateValidate manifest before applying
--forceForce apply by deleting and recreating
Examples

Pro tip

Always use `--dry-run=server` not `--dry-run=client` — server-side dry run runs full validation including admission webhooks, catching errors that client-side validation misses.
