Mount filesystems to make them accessible.

⚠ Risks & cautions
  • Mounting over a non-empty directory hides its contents until it is unmounted.
  • Wrong options (remount,ro, -o bind) can break running services; `umount -l` leaves processes with stale handles.
  • Test /etc/fstab changes before rebooting — a bad line can drop the machine into emergency mode (add nofail where appropriate).

What it does

mount attaches filesystems (block devices, network shares, virtual filesystems) to the directory tree. Without arguments, shows all currently mounted filesystems. Persistent mounts are configured in /etc/fstab.

Common flags
FlagMeaning
-t --typesFilesystem type (ext4, nfs, tmpfs, etc.)
-o --optionsMount options (ro, rw, noexec, etc.)
-a --allMount all filesystems from /etc/fstab
--bindBind-mount a directory to another location

Pro tip

Use `mount -o remount,ro /` for emergency read-only remount during disk issue investigation — prevents further writes while you diagnose. Reverse with `remount,rw`.
