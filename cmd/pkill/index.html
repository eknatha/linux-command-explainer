pkill

Send signals to processes matched by name or attributes.

high risk

high riskCan kill unintended processes if pattern is too broad.
⚠ Risks & cautions
  • Matching is by substring: `pkill java` kills every JVM on the host.
  • Preview with `pgrep -a <pattern>`; prefer `pkill -x` (exact) or `-u <user>`.
  • SIGKILL (-9) skips cleanup.
Safer / dry-run alternatives
pgrep -a <pattern>Preview which processes match.
pkill -x -TERM <name>Exact name, graceful signal.
What it does

pkill sends signals to all processes matching a name pattern or other criteria. The default signal is SIGTERM (graceful shutdown). With -9 (SIGKILL), it force-kills. Always verify with pgrep first — pkill applies to all matches.

Common flags
FlagMeaning
-f --fullMatch against full command line
-u --euidMatch by user
-signalSignal to send (default: SIGTERM/15)
-9Force kill (SIGKILL)
-HUPSend SIGHUP (reload config for many daemons)

Pro tip

Always run `pgrep -a pattern` before `pkill pattern` to see exactly what will be affected — pkill's output tells you nothing about what it killed.
