selinux (advanced)

Manage SELinux mandatory access control policies.

⚠ Risks & cautions
  • Setting permissive/disabled removes mandatory access control — fix the denial instead.
  • chcon changes do not survive a relabel; use semanage fcontext + restorecon.
  • Going from disabled to enforcing needs a full relabel (touch /.autorelabel) and a reboot.
Safer / dry-run alternatives
ausearch -m avc -ts recent | audit2whyFind out what is being denied.
semanage fcontext -a -t <type> '<path>(/.*)?' && restorecon -Rv <path>Fix the label permanently.
What it does

SELinux (Security-Enhanced Linux) enforces mandatory access control policies beyond traditional file permissions. When applications fail silently, SELinux denials are often the cause. Use getenforce/setenforce to check and toggle mode, and audit2why to understand denials.

Examples

restorecon -Rv /var/www/htmlRestore default SELinux file contexts · explain & risk-check →
Pro tip

Before permanently disabling SELinux, try `setenforce 0` and test — if the issue resolves, use `audit2allow` to create a proper policy instead of leaving enforcement disabled.
