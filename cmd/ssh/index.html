ssh

Securely connect to a remote host over an encrypted SSH tunnel.

medium risk

medium riskGrants remote access; misconfigured keys or jump hosts can be security risks.
⚠ Risks & cautions
  • Verify host-key fingerprints on first connection; never disable StrictHostKeyChecking in scripts for production.
  • Agent forwarding (-A) lets the remote host use your keys — prefer -J (ProxyJump).
  • Port forwards (-L/-R/-D) can expose internal services; bind to 127.0.0.1.
What it does

ssh creates an encrypted connection to a remote machine. Key-based authentication (-i) is strongly preferred over passwords. -J enables jump host proxying through bastion servers. -L/-R set up local/remote port forwarding tunnels.

Common flags
FlagMeaning
-iSpecify private key file for authentication
-pConnect to a non-standard SSH port
-LLocal port forwarding: tunnel a remote port to localhost
-RRemote port forwarding: expose local port on remote host
-JJump/bastion host proxy
-NDo not execute a remote command (useful for tunnels)
-vVerbose mode for debugging connection issues

Pro tip

Configure `~/.ssh/config` with Host aliases — replace `ssh -i key.pem -p 2222 user@long.host.com` with just `ssh prod`.
