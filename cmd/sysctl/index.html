sysctl

Read and write kernel parameters at runtime.

⚠ Risks & cautions
  • Runtime changes affect the whole host immediately and are lost on reboot unless persisted in /etc/sysctl.d/.
  • Wrong values (rp_filter, ip_forward, tcp tuning, vm.overcommit, kernel.panic) can break networking or crash services.
  • Record the old value first (sysctl -n <key>) so you can roll back.
Safer / dry-run alternatives
sysctl -n <key>Note the current value before changing it.
sysctl --systemReload from config files to undo runtime experiments.
What it does

sysctl reads and modifies kernel parameters in /proc/sys/ at runtime. Changes are immediate but not persistent unless written to /etc/sysctl.conf or /etc/sysctl.d/. Used for tuning network stack, enabling IP forwarding, configuring VM behavior, and hardening.

Common flags
FlagMeaning
-a --allPrint all kernel parameters
-w --writeSet a parameter value
-p --loadLoad from a file (default: /etc/sysctl.conf)
-n --valuesPrint only the value, not the name
Examples

Pro tip

For K8s nodes, always verify: `sysctl net.bridge.bridge-nf-call-iptables=1` and `net.ipv4.ip_forward=1`. Missing these causes pod networking failures that are hard to trace.
