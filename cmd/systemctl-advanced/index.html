systemctl advanced (advanced)

Advanced systemd service management: dependencies, drop-ins, and masking.

medium riskMasking and disabling services affects system functionality.
⚠ Risks & cautions
  • Masking a unit prevents any start — even by dependencies; remember to unmask.
  • `isolate`, `rescue` and `emergency` stop most services immediately.
  • `systemctl edit` creates drop-ins; run daemon-reload and verify with `systemctl cat`.
What it does

Beyond start/stop/status, systemctl manages service dependencies, unit file overrides (drop-ins), masking (preventing any start), and systemd's boot analysis. Drop-in files in /etc/systemd/system/service.d/ override specific unit directives without editing originals.

Pro tip

Use `systemctl edit service` for drop-in overrides instead of editing unit files directly — overrides survive package upgrades and are clearly separated in `/etc/systemd/system/service.d/override.conf`.
