truncate

Shrink or extend a file to a size

high risk

interactive breakdown — edit the command and press Explain
$ 
high riskCutting a file shorter permanently discards data beyond the new size.
⚠ Risks & cautions
  • Data past the new size is gone — there is no undo.
  • Truncating a log that a process holds open is usually fine, but truncating a database or data file corrupts it.
  • Check the filename carefully; this runs without confirmation.
Safer / dry-run alternatives
cp app.log app.log.bak && truncate -s 0 app.logKeep a copy before emptying
logrotate -f /etc/logrotate.d/<app>Let logrotate manage log files
What it does

Sets a file to an exact size. `truncate -s 0 file` empties it without deleting it; extending creates a sparse file.

Common flags
FlagMeaning
-sNew size, e.g. 0, 100M, +1G
-cDo not create missing files
Examples
