ulimit

Get and set resource limits for the current shell and child processes.

medium risk

interactive breakdown — edit the command and press Explain
$ 
medium riskIncorrect limits can starve processes or hide resource issues.
⚠ Risks & cautions
  • Limits set in a shell apply to that shell and its children only; persistent limits live in /etc/security/limits.d/ or systemd LimitNOFILE=.
  • `unlimited` removes protection against runaway processes.
What it does

ulimit controls resource limits (open files, processes, stack size, core dumps) for the shell and its children. Limits come in two types: soft (current limit, can be raised by user) and hard (maximum ceiling, only root can raise). Critical for high-connection services.

Common flags
FlagMeaning

-u --nprocMax user processes

Pro tip

High-traffic services (nginx, node) need `nofile` set to 65536+ in /etc/security/limits.conf or systemd unit (LimitNOFILE=65536). Default of 1024 causes 'too many open files' at load.
