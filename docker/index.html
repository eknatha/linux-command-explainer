medium riskContainers run as root by default; misconfigured mounts can expose the host filesystem.
⚠ Risks & cautions
  • Anyone who can run docker commands is effectively root on the host (the docker group is root-equivalent).
  • Mounting /var/run/docker.sock or / into a container hands that container control of the host.
  • Pin image tags or digests instead of :latest, and avoid running containers as root.
What it does

docker manages the full container lifecycle. The daemon runs as root — use rootless Docker or podman for better security in production. Containers share the host kernel, so namespace escapes are a real risk on unpatched kernels.
