mysqldump

Back up MySQL/MariaDB databases to SQL files.

⚠ Risks & cautions
  • Without --single-transaction (InnoDB) or --lock-tables the dump can block writes or be inconsistent.
  • A password on the command line (-pSECRET) is visible in `ps` — use an option file with 600 permissions.
  • Large dumps can fill the disk — check free space and compress via a pipe (| gzip).
What it does

mysqldump exports MySQL/MariaDB databases to SQL files. For InnoDB tables (the standard), always use --single-transaction for a consistent backup without locking. The --routines and --triggers flags include stored procedures and triggers.

Common flags
FlagMeaning
--single-transactionConsistent backup without locking (InnoDB)
--routinesInclude stored procedures and functions
--triggersInclude triggers
--no-dataSchema only, no data
--databasesSpecify multiple databases
Examples
mysqldump -h localhost -u root -p --single-transaction mydb > mydb.sqlFull consistent backup of one database · explain & risk-check →
mysqldump -u root -p --single-transaction --all-databases | gzip > all_dbs.sql.gzAll databases compressed · explain & risk-check →
mysqldump -u root -p --no-data mydb > schema.sqlSchema only (no data) · explain & risk-check →
mysql -u root -p mydb < mydb.sqlRestore from SQL backup · explain & risk-check →
Pro tip

Always use `--single-transaction` with InnoDB tables — without it, mysqldump locks all tables for the duration of the backup, causing write queuing on busy production databases.
